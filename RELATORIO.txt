1. VISAO GERAL
----------------------------------------------------------------

O Farmacia Facil Admin e o painel administrativo web (Flutter Web)
da plataforma Farmacia Facil. Permite ao administrador gerenciar
usuarios, farmacias (aprovacao/ativacao) e pedidos, alem de exibir
um dashboard com metricas basicas.

Ecossistema:
  - App Usuario (farmacia.facio) - PRODUCAO
  - App Vendedor (farmacia-facil-vendedor) - PRODUCAO
  - App Admin (este projeto) - FASE 4 (MVP funcional)
  - App Entregador - NAO INICIADO (Fase 3)

Projeto Firebase compartilhado: farmacia-facil-b980c
Conta: sandroprogramatattoo@gmail.com

2. STACK TECNOLOGICA
----------------------------------------------------------------

  Framework: Flutter 3.38.5 (Dart 3.10.4) - alvo Web
  Estado: flutter_riverpod 3.3.2 (Notifier API)
  Navegacao: go_router 17.5.0
  Backend: Firebase (firebase_core 5.1.0, firebase_auth 7.0.1,
           cloud_firestore 7.1.0)
  Utilitarios: intl 0.20.3, shared_preferences 2.5.5
  Lints: flutter_lints 6.0.0
  Deploy: GitHub Actions -> GitHub Pages (peaceiris/actions-gh-pages)

3. ARQUITETURA E ESTRUTURA
----------------------------------------------------------------

lib/
  main.dart                 Inicializacao Firebase + ProviderScope
  firebase_options.dart     Config do projeto farmacia-facil-b980c
  app/
    theme.dart              Tema escuro (azul) Material 3
    routes.dart             GoRouter + redirecionamento por auth
  models/
    user_model.dart         Usuario (id,name,email,phone,address,...)
    pharmacy_model.dart     Farmacia/Vendedor (isApproved, isActive,...)
    order_model.dart        Pedido (status, itens, total, entrega)
  providers/
    auth_provider.dart      AdminAuthNotifier (login + verificacao admins)
    users_provider.dart     Carrega colecao 'users'
    pharmacies_provider.dart Carrega 'pharmacies' + updatePharmacy
    orders_provider.dart    Carrega 'orders' ordenados por createdAt
  screens/
    auth/login_screen.dart  Login (email/senha)
    dashboard/dashboard_screen.dart  Cards de metricas
    pharmacies/pharmacies_screen.dart  Listagem + acoes
    users/users_screen.dart  Listagem de usuarios
    orders/orders_screen.dart  Listagem + filtro por status
  widgets/
    admin_shell.dart        Shell com NavigationRail

Colecoes Firestore consumidas:
  - users       (app usuario)
  - pharmacies  (app vendedor, com isApproved/isActive)
  - orders      (app usuario/vendedor)
  - admins      (controle de acesso do painel)

6. RISCOS E PONTOS DE ATENCAO
----------------------------------------------------------------

  1. Seguranca:
     - Acesso controlado apenas pela existencia de doc em 'admins'.
       Nao ha custom claims nem verificacao de role no token.
     - Regras do Firestore devem ser refinadas antes de producao publica.
     - Chaves do Firebase expostas no cliente (normal para web, mas
       regras sao a protecao real).

  2. Escalabilidade:
     - Carregamento completo de colecoes (sem paginacao/limit).
       Pode degradar com crescimento de dados.
     - Sem cache local (shared_preferences instalado mas nao usado).

  3. UX:
     - Sem busca/filtros na maioria das telas.
     - Sem confirmacao antes de acoes destrutivas.
     - Sem notificacoes/toasts de sucesso/erro.

  4. Observabilidade:
     - Sem analytics, crash reporting ou logging estruturado.

  5. Compatibilidade:
     - App web-only (sem build mobile/desktop configurado).
     - Base href fixo para GitHub Pages.

9. CONCLUSAO
----------------------------------------------------------------

O painel admin esta em estagio MVP funcional: autenticacao
restrita, dashboard basico, gestao de farmacias (aprovacao/
ativacao), listagem de usuarios e pedidos com filtro por status.
A base arquitetural e solida e consistente com o ecossistema
(Riverpod + go_router + Firebase), e o deploy automatizado
esta operacional.

Para evolucao para producao robusta, recomenda-se priorizar:
seguranca (regras Firestore + custom claims), escalabilidade
(paginacao + tempo real) e UX (busca, feedback, detalhes).
